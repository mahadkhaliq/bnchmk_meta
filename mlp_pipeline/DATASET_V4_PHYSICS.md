# V4 Coupled-Lorentz Synthetic Dataset

## Purpose

This document records the generation and validation of the v4 dataset used for
future geometry-to-power-transmission experiments. It is a large,
physics-model-generated dataset, separate from the original CST-based
v1/v2/v3 datasets.

V4 contains 20,000 samples for every square metasurface array from 1x1 through
10x10: 200,000 samples in total.

## Dataset Location

The completed release is stored on the Malof Lab computer, not in Git:

```text
/mnt/DATA/mkfqm/rep_benchmark/datasets/v4_coupled_lorentz_20k_1to10/
```

Top-level contents:

```text
MANIFEST.json
synthetic_1x1.npz
synthetic_2x2.npz
...
synthetic_10x10.npz
metadata/per_scale_manifests/
logs/
_staging/
```

The assembled release occupies about 1.6 GB. `MANIFEST.json` is the
authoritative record of the fitted model, model hash, frequency grid, feature
layout, per-scale files, and generation settings. Per-scale manifests are kept
under `metadata/per_scale_manifests/` for provenance.

## What The Data Represents

The target is power transmission:

\[
T(f) = |S_{21}(f)|^2
\]

It was generated by the coupled-Lorentz forward model from
[`DaryLu0v0/physic-multi-scale`](https://github.com/DaryLu0v0/physic-multi-scale),
using its `add-na-fitting-code` implementation and the fitted
`real_model_na_v1.json` artifact.

This is **synthetic physics-model data**, not newly run CST simulation data.
The fitted model encodes an isolated-cell geometry-to-Lorentz map plus a learned
coupling operator. It is useful for scale studies, pretraining, augmentation,
and controlled architecture experiments. It should not replace an independent
CST holdout when reporting real-simulation generalization.

## Common Generation Settings

| Setting | Value |
|---|---|
| Date generated | 2026-07-23 |
| Samples per size | 20,000 |
| Array sizes | 1x1 through 10x10 |
| Total samples | 200,000 |
| Frequency band | 12.0 to 26.0 GHz |
| Frequency points | 2,001 |
| Output | power transmission `T` |
| Transmission forward | thin-sheet (`sheet`) |
| Coupling artifact | `real_model_na_v1.json` |
| Coupling form | hybrid NA operator with periodic-image radius 5 |
| Geometry sampling | flat isolated-resonance-frequency sampling |
| Random seed for NxN | `20260723 + N` |
| Feature order | `[d, l, w, g]` in mm |
| Geometry layout | atom-major, row-major flattened `geom` |

The flat-resonance sampler targets a broad isolated-resonance distribution.
When a requested resonance is unreachable for a sampled set of the other
geometry variables, that atom falls back to natural geometry sampling. The
generator reports such fallback counts in the per-scale logs.

The fitted geometry box used by the forward model is:

| Feature | Range (mm) |
|---|---:|
| `d` | 1.4806 to 1.6999 |
| `l` | 0.6509 to 1.4758 |
| `w` | 0.0600 to 0.1400 |
| `g` | 0.0500 to 0.0999 |

## Generation Procedure

Generation ran on `cengr-42ksgh4.engineering.missouri.edu` using four NVIDIA
RTX PRO 6000 Blackwell GPUs, each with approximately 96 GB of memory. The
user-level Conda environment was:

```text
/home/mkfqm/software/miniconda3/envs/metasurface-gen
Python 3.11, NumPy, PyTorch 2.11.0+cu128
```

No sudo or system-level installation was used. The launch script is
[`run_physics_20k_1to10.sh`](run_physics_20k_1to10.sh). It assigned independent
scales to separate GPUs, wrote each scale to an isolated staging directory, and
assembled the final root-level dataset only after all ten generation processes
completed.

The assembly step was performed by
[`assemble_physics_dataset.py`](assemble_physics_dataset.py). It checks that
each staging directory has exactly one scale manifest, refuses to overwrite an
existing release file, and verifies that shared generation settings agree before
writing the combined manifest.

## Use With This MLP Pipeline

The schema matches the v3-style `geom`/`T` loader format and uses the same
atom-major `[d,l,w,g]` ordering. However, v4 is **not yet registered** in
`config_powertx.py`.

- For `1x1`, `2x2`, and `3x3`, an existing v3 grid specification can be paired
  with `POWERTX_NPZ_PATH` to point at the corresponding v4 file.
- For `4x4` through `10x10`, add explicit v4 entries to `_SPECS` with
  `input_dim = 4*N*N`, `grid_n = N`, and `output_dim = 2001` before using the
  normal training scripts.
- These files do not supply train/validation/test partitions. Apply a
  deterministic sample-level split, fit geometry normalization on training data
  only, and retain the seed in each experiment record.

## Notebook Handoff

Before training, the notebook should first:

1. Read `MANIFEST.json` and select one scale at a time.
2. Plot representative `T(f)` curves using `freq_GHz` and `T`.
3. Check geometry and target distributions per scale.
4. Use identical seeds and samples when comparing models.
5. Keep synthetic-v4 results separate from CST-v1/v2/v3 results in plots and
   tables.

The v4 frequency grid matches v3 (12-26 GHz, 2,001 points), but the source and
sample counts differ. Any MSE comparison across v3 and v4 should therefore be
labelled as a cross-dataset comparison, not an architecture-only comparison.
